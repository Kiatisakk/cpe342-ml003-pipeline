Anomaly types seem to come in groups of ~200-300 rows each (account takeover: friend_removes+currency_transfers shock; account selling: skill_rating+skill_trajectory jump; geo/VPN jump; bots; low activity; low communication; low stability). A candidate group of n rows improves F3 only if its precision is > ~9% (F3/10).
Already checked, no signal: single-metric skill_trajectory tail outside the union (continuous tail, not a cluster); "gradual drift" (monotone 4-period trends) vs a period-shuffle null; histogram-gap scans of mean/std/min/max/slope per metric.

GOALS
A. Find the missing anomaly type(s): look for compact groups of ~100-300 rows that are clearly separated from normal behaviour in a way the current rules miss - multivariate/stationary shifts in pairs or ratios of features (e.g. ip_hash_entropy x device_count, purchase/refund/currency patterns, login_count vs activity, session mean vs std), flag-column combinations (password_changed, vpn_usage, suspicious_login_time, mass_item_sale) with behaviour, period-specific shifts in periods 2 or 1, impossible values. Use proper unsupervised methods (robust Mahalanobis / per-feature density, Isolation Forest, LOF, GMM / DBSCAN on standardized summary features, autoencoder reconstruction error) and inspect the top-ranked rows outside the union for structure. For every candidate group report: size, overlap with the union, the defining rule, why it looks like a distinct injected type (separation / gap evidence), and a confidence level.
B. Course compliance: the course asks for unsupervised anomaly-detection techniques (Isolation Forest, Autoencoder, ...), not hand rules only. Build a model-based pipeline (e.g. per-group robust-z / IF / AE detectors combined by voting) whose final flagged set reproduces the union (report the overlap) plus any new groups, so the team can describe it as an unsupervised ensemble in the report.
C. Produce submission-ready T5 vectors: t5/research/t5_candidates/<name>.csv (id ANS00001..ANS25889 in test.csv order, pred 0/1) = union + each new candidate group separately, ranked by confidence, so the team can probe them one at a time on the leaderboard.
